## Global release controls

- M0 is verified: M0-FOUNDATION-001 passed fresh-login native-window re-verification, and PR `#1` remains merged as `3e6cf85`.
- M1 is complete through PR #29 (`6f7d647`): process/PTY launch, bounded event streaming and admission, timeout/cancel/pause/resume, process-tree and shutdown cleanup, stdin delivery and waiting-input detection, secret-redacted metadata, isolated worktrees, termination durability, a 1 MiB pending-stdin cap, and authenticated crash-orphan worktree recovery all pass the ADR-007 gate.
- M1.5 First Capture Journey is the next dependency-ready milestone, but it has not started. The autonomous loop is paused at the user's checkpoint and must not resume without an explicit user instruction.
- A single active milestone PR is permitted.
- Each completion gate requires linked implementation evidence, verification evidence, and PR status in the ledger.
- Product progress is a visible vertical slice. Subsequent domain/backend work must ship with its usable app surface; internal-only fixes may unblock a slice but do not count as product progress.
- Every UI-bearing slice has a UX gate record containing the exact tested commit and packaged build, named scenario states, Computer Use result and evidence path, Opus UX contract/implementation/review results, independent gpt-5.6-sol technical review, and `user_verdict: pending|approved|rejected`.
- UX evidence lives under `.loop/verification/<milestone>/<slice>/ux/` and retains screenshots, accessibility trees, a scenario log, real-data/backend provenance, and the fresh independent Opus visual review. Real Computer Use must exercise the packaged `.app`; process/window-count smoke, unit tests, previews, and mocks cannot satisfy product verification.
- A UI PR pauses before merge with `user_verdict: pending`. Approval permits the remaining merge gates; rejection reopens the same milestone and slice. Opus or Computer Use unavailability blocks the slice rather than downgrading the gate.
- ADR-007 remains the technical merge gate: a fresh local `scripts/verify-m0.sh` parity log plus an independent Codex gpt-5.6-sol review with all confirmed blockers resolved. GitHub Actions status is not required or consulted.
- M14 may close only against the full specification, including positioning and qualitative success criteria.
