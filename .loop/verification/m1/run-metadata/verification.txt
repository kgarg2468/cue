# M1 slice: run metadata + secret redaction (S10-010)

Spec: section 10 local runtime responsibilities — "redact secrets from logs" and
"record process and environment metadata" (lines 656-657); feeds section 14 audit-log
fields (final status, output artifacts).

## Behavior
- Every spawned run emits exactly one run_metadata frame after the final run_output
  and before run_exit, on all terminal paths (natural exit, timed_out, cancelled):
  pid, pgid, executable, arguments, working_directory, started_at/finished_at
  (RFC3339 UTC), duration_ms, environment_variable_names (sorted NAMES only — never
  values), and the run's total redaction count. Spawn-failed runs emit only the
  spawn_failed run_exit.
- run_output (stdout and stderr) is scanned before emission; matches of a
  conservative pattern set are replaced with [REDACTED]: AWS AKIA ids, GitHub
  gh?_/github_pat_ tokens, Slack xox?- tokens, OpenAI-style sk- keys, Bearer
  credentials (keeping the word Bearer), key=value / key: value assignments for
  api_key/secret/token/password/passwd/authorization (keeping the key name), and PEM
  private-key blocks (unterminated BEGIN redacts to end of frame). Patterns are
  compiled once (OnceLock, regex crate).
- Known limitation (documented in code): a secret split across two pipe read chunks
  can escape redaction.
- Swift ProcessEvent gains .metadata(runID, pid, durationMilliseconds, redactions)
  decoding run_metadata; richer field decoding flagged as future work.

## Independent review dispositions (Codex gpt-5.6-sol, read-only, high effort)
Report: review-report.md. Findings confirmed against the code and dispositioned:
- CONFIRMED blocker — the 8KiB outbound frame cap could make an oversized
  run_metadata frame (large arguments + env names) unwind the connection before
  run_exit. Fixed: progressive truncation (clear env names, then arguments, keeping
  all scalar fields) sized against the exact cap check, and a metadata write error
  no longer suppresses run_exit (registration released, run_exit attempted, error
  propagated after). New test oversized_run_metadata_is_truncated_before_run_exit;
  runtime demo shows partial truncation at a 7000B argument (env cleared, argument
  kept) and full truncation at 7904B, with run_exit 0 both times.
- CONFIRMED major — finished_at/duration_ms were captured after the drain-thread
  joins, so client socket backpressure inflated reported duration. Fixed: captured
  at the supervision loop's terminal break, before the joins; frame ordering
  unchanged.
- CONFIRMED major — the new current_dir()? propagated failure before spawn (deleted
  backend cwd would EOF every start request with no frame). Fixed: non-propagating
  fallback to an empty working_directory.
- Redaction pattern gaps (values under 4 chars, single-quoted/whitespace values,
  Bearer under 8 chars) and prose over-redaction ("Bearer authentication is
  required", "parser token: identifier") — accepted trade-offs of the documented
  fixed pattern set; no change.
- Pre-existing zero-terminal-frame error paths (drain-thread spawn failure, fcntl,
  try_wait/wait errors after spawn) — verified pre-existing on main, out of this
  slice's scope; flagged as future durability work.
Post-fix evidence: cargo-test-postfix.log (15+13+31 green),
verify-m0-parity-postfix.log (exit 0), runtime-demo-postfix.log.
