M1 pause/resume slice verification — 2026-07-18 (cycle 9)

Slice: versioned pause_process/resume_process requests over the Unix socket
protocol (spec adapter API: pause(runId)/resume(runId), spec lines 603-604;
one-click pause, line 865). Pause SIGSTOPs the run's whole process group,
resume SIGCONTs it; accepted/not_found is existence-based like cancel. The
registry value became RunControl {cancelled, paused, pgid}; the supervision
loop stores the pgid post-spawn and a SeqCst store-then-load handshake on
(paused, pgid) ensures a pause landing in the register-to-spawn window is
applied by exactly one side. The timeout deadline deliberately keeps ticking
while paused, and cancel/timeout/shutdown SIGKILL a stopped group unchanged.
Swift IPCClient gains pauseProcess/resumeProcess mirroring cancelProcess.

Independent review (Codex gpt-5.6-sol, high effort, static): 1 blocker,
1 major, 3 minor. Dispositions after code verification (fixes implemented by
a second sol worker, high effort, diff-gated to lib.rs + process_lifecycle.rs,
+42/-18):
- FIXED (blocker): the SeqCst handshake guaranteed visibility but not signal
  ordering — a stalled post-spawn SIGSTOP could land after a resume, leaving
  the group stopped with paused=false. All {pgid, paused} transitions and
  their SIGSTOP/SIGCONT delivery now serialize under the registry mutex
  (pause/resume hold the lock through signalling; publish_pgid does the
  post-spawn store+conditional-SIGSTOP under the same lock).
- FIXED (major): pause/resume could signal a reaped, reusable pgid because
  the registry entry outlives the reap until drains join. New
  RunRegistration::retire zeroes the published pgid under the mutex; every
  terminal branch retires after the group kill and before reaping
  (TimedOut/Cancelled) — the Exited branch's try_wait-to-retire residual
  matches the pre-existing inherent kill-after-reap pgid-reuse window and is
  commented as such.
- FIXED (minor): resume-state polling treated zombie 'Z' as resumed; the
  helper now rejects both 'T' and 'Z' when expecting a running state.
- FIXED (minor): the paused-timeout test's 1500ms budget could expire on
  slow CI before the pause round-trip (flaky not_found); raised to 5000ms.
- NOTED (minor, no code change): the integration pause test waits for output
  before pausing, so the register-to-spawn pause window is not exercised
  end-to-end; it is covered by the lib unit test
  (pause-before-pgid records without signalling) and is now enforced by
  mutex serialization rather than lock-free ordering.
