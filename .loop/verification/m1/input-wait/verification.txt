# M1 slice: waiting-for-input detection (S10-009)

Spec: section 10 Responsibilities — "detect when an agent is waiting for input";
feeds the section 18.17 "Needs input" notification surface (later milestone).

## Change

- start_process gains optional `input_wait_detect_milliseconds` (positive
  integer; absent/null = disabled, byte-identical prior behavior; invalid
  values rejected like invalid timeout_milliseconds). Old backends ignore the
  field (no deny_unknown_fields), same precedent as `pty`.
- When enabled the backend emits `{"type":"run_input_waiting","run_id":...,
  "quiet_for_milliseconds":N}` at most once per quiet episode, when ALL hold:
  quiet >= threshold since last activity (spawn, output chunk, or stdin bytes
  written to the child), stdin delivery queue empty and not mid-write, and
  child CPU time advanced < 30ms over the window (libc::proc_pidinfo
  PROC_PIDTASKINFO, mach-units converted via mach_timebase_info). Activity
  resets the episode. Never emitted after the supervision loop chooses a
  terminal path. Works for pipe and PTY runs. Frames use the synchronized
  writer path; supervision tick stays nonblocking (stdin try_lock first,
  full recheck under the locks before emitting).
- Swift IPCClient: `inputWaitDetectMilliseconds: Int? = nil` on
  startProcess/startProcessRequest (serialized only when set); ProcessEvent
  gains `.inputWaiting(runID:quietForMilliseconds:)` with a decode branch
  (orchestrator addition — the worker-scoped API would otherwise throw
  invalidProcessEvent on the new frame).
