## Design decisions
- kind is REQUIRED and case-sensitive from the §6.3 set (important, decision,
  action, question, delegate, research); omitted, null, blank, or unknown
  kinds are invalid_add_marker. This differs from session kind (optional)
  because a marker IS its intent.
- note mirrors the speaker convention: optional, omitted when absent,
  explicit null rejected, trimmed non-blank, ≤4096 bytes; escape-heavy notes
  are caught by the draft → frame-bound check → insert ordering.
- at_ms is a non-negative whole millisecond (same milliseconds_field parsing
  as source timings); validation order fields → unknown_session → draft →
  bound check → insert, matching sources exactly.
- list_markers pages chronologically (at_ms ASC, id ASC, limit 50, limit+1
  probe, 8 KiB byte budget popping from the END so the beginning survives).

## Review round 1 (Sol gpt-5.6-sol xhigh): FAIL, 1 MAJOR + 2 MINOR
- MAJOR (confirmed, fixed red-first): admission bound-checked the add/create
  response envelope, but a single-item list envelope is ~20 bytes larger, so a
  boundary-sized escape-heavy record could persist yet be permanently
  unlistable (the byte budget pops even a lone record). The same latent gap
  existed in the merged sources and sessions paths. Fix: admission now probes
  the single-item LIST envelope for markers, sources, AND sessions —
  accepted implies listable alone. Three boundary-sweep tests pin the
  invariant (red output in red-evidence.log; sweeps capped below the 8 KiB
  request bound, which drops oversized request connections by design).
- MINOR (recorded, deferred as in cycle 21): typed envelope fields mean a
  previously-ignored junk field like "note": 7 now fails deserialization on
  any message; inherent to the shared-envelope design, batched with the
  protocol-hardening slice.
- MINOR (recorded, deferred as in cycle 21): Swift decoders are permissive
  (accept unknown kinds / negative at_ms); client-hardening slice.

  persistence + 58 process_lifecycle); verify-m0-r2.log exit 0.
