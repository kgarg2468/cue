Slice: optional typed session kinds (S05-001) — migration 2 adds a nullable

include kind only when set; Swift Session gains optional kind.

## Design decisions
- Valid kinds (case-sensitive): meeting, conversation, presentation, pair_work,
  personal_note, imported_audio (spec §5 line 169). "Auto"/uncategorized (spec
  §18.4 "does not require categorization") is represented by OMITTING the kind
  field — "auto" is not a wire value and is rejected.
- Kind is validated before Session::draft, preserving the draft → frame-bound
  check → insert ordering from the previous slice.
- Migration 2 is a nullable ALTER TABLE ADD COLUMN: pre-existing rows stay
  valid with NULL kind, exercised by a unit test on a hand-built v1 store and
  by the runtime demo.

## Security invariants checked
- Protocol change additive; unknown kinds rejected before any persistence.
- Store file/sidecar permissions unchanged (0600 in 0700-when-created dir).
- User store at ~/Library/Application Support/CaptureDelegate untouched by the
  full verification run (pre-existing sessions dir only, mtime 2026-07-19).

## Known bounds carried forward
- No session-kind update/rename protocol yet (later M2 slice).
- Swift client sends kind as a raw optional String; a typed enum is deferred
  (flagged by the implementation worker).
