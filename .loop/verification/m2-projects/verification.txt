# M2 slice 11 — durable projects + session links (S05-002 "related projects",
# S02-INC-08, spec §12; roadmap M2 exit criteria "project links survive restart")

## Contract
- Migration 10: projects (id, name <= 4096B trimmed non-blank, stamps) +
  session_projects link table (composite PK, linked_at_ms) + link-order index.
- create_project admission probe uses the single-item list_session_projects
  envelope — the LARGER of the read frames (its response_type is 8 bytes
  longer) — so an admitted project stays listable alone AND through a session.
- link_session_project: both ids required (double-Option), unknown_session /
  unknown_project splits, INSERT OR IGNORE + changes()==0 duplicate detection
  (race-free) -> duplicate_project_link. Reply frame serialized BEFORE the
  write so nothing persists behind an unwritable reply. No probe needed: the
  frame carries no client text (commented).
- list_session_projects: link order = ORDER BY linked_at_ms ASC, rowid ASC.
  Deliberate deviation from my dispatch (project_id tie-break): back-to-back
  links land in the same millisecond, and project ids are creation-ordered, so
  a project_id tie-break would reintroduce creation order — exactly what the
  red test pins against. rowid is the link row's own insertion order.
- Deliberately NO global list_projects arm this slice.
- Swift Project/ProjectPage/SessionProjectLink + three methods.
