"accepted implies listable alone" admission invariant to run records

## Design decisions
- Probe is built by cloning the REAL draft record (identical generated id,
  so no id-length race), then substituting worst-case terminal fields:
  status "interrupted" (longest status), exit_code i32::MIN (longest exit
  code), error_code "capacity_exhausted" (longest code in the protocol —
  it never persists today, which gives the probe headroom against future
  persisted codes), ended_at_ms mirroring started_at_ms (same clock, same
  width). Rejection releases the run-id registration and process slot and
  answers invalid_start_process before any insert.
- The probe sits after the duplicate/capacity gates (where the real draft
  exists) mirroring the established insert-failure rejection path.
- Conservative over-rejection window (~50 bytes at the 8 KiB boundary) is
  deliberate: a run near the bound that would be rejected only under the
  worst-case terminal shape has no legitimate use.

## Review round 1 (Sol): FAIL, 1 MAJOR + 1 MINOR — both fixed
- MAJOR: probe ended_at_ms copied started_at_ms, but termination resamples
  the wall clock, which a forward clock step can widen past the start's
  serialized width. Probe now uses i64::MAX (the serialized ceiling). No
  black-box red test is possible without clock control; correctness is
  static (i64::MAX is the maximum width the field can serialize).
- MINOR: the sweep only exercised clean exits. It now sweeps BOTH terminal
  shapes per size — /bin/echo (exit_code, no error_code) and a nonexistent
  executable (null exit_code, persisted error_code spawn_failed) — and
  asserts the persisted error code survives listing, so a probe that stops
  budgeting persisted error codes fails the test.
- verify-m0-r2.log exit 0 after remediation; 131 Rust tests green.
