## Design decisions
- Record inserted after the duplicate_run_id gate and slot/write-timeout setup,
  immediately before worker spawn, so no failure path leaves an unclosable
  "running" row; insert failure releases the admission and reports
  store_unavailable.
- finish_run is bound to RunTerminal's existing one-shot guard (record key is
  *taken* under the guard) → at-most-once durable close, written before the
  run_exit frame without holding the ClientWriter mutex; a store error is
  reported loudly but never withholds the client's frame (the row is corrected
  by the next startup sweep). Thread-spawn failure closes the record with
  internal_error.
- One backend per store: a lifetime flock on the `<store>.owner` sidecar is
  taken right after open_store, before any lifecycle rewrite. The socket bind
  proves socket ownership, not store ownership (Sol round 2) — a second
  backend on a different socket but the same store now fails startup with
  "store … is already owned by another backend". Kernel releases the lock on
  process death, so no stale-lock recovery is needed.
- No terminal-write retries: ownership rules out cross-process busy
  contention, so retrying a failed finish_run only stalls run supervision
  (a 3×busy-timeout retry loop could hold a run terminal ~15s — Sol round 2);
  a single attempt + startup-sweep correction is strictly better.
- Startup sweep (running → interrupted + ended_at_ms) is fatal on failure and
  runs under the ownership lock, before the accept loop serves any request,
  so no client can read a page claiming a dead run is live and a backend that
  cannot recover state refuses to serve.
- session_id on the wire uses the double-Option convention: omitted = unlinked,
  explicit null = invalid_start_process, unknown = unknown_session before
  admission. add_source/list_sources semantics unchanged.
- list_runs pages newest-first (started_at_ms DESC, id DESC, limit 50, limit+1
  probe, 8 KiB budget popping from the end).

## Review rounds (Sol gpt-5.6-sol xhigh)
- Round 1 FAIL: sweep ordered before the duplicate-launch liveness gate and
  non-fatal; terminal close droppable; list_runs bounds untested. Fixed
  red-first (sweep after bind + fatal; bounds/truncation test; duplicate
  launch cannot interrupt a live backend's runs).
- Round 2 FAIL: bind ≠ store ownership; retry loop violates supervision
  bound. Fixed red-first with the owner flock + retry removal above.

## Security invariants checked
- Protocol change additive; all 58 process_lifecycle tests untouched and green.
- Only admitted runs persist; rejected/refused runs leave no record.
- Owner sidecar created 0600; store hygiene unchanged; user store untouched.

## Known bounds carried forward (worker-flagged, recorded)
- capacity_exhausted / shutdown-cancelled refusals persist no record (they
  never reach admission) — deliberate for now, revisit with run events.
- Swift startProcess has no session-link parameter yet (wire-only linkage).
- IPCClientError.invalidSessionResponse is now a misnomer across three record
  types (rename is API-breaking; batch with a client-hardening slice).
- status/error_code are free-form strings in the store; no per-session runs
  index yet.
